# creating-job-application-docs — Job Application Documents

履歴書・職務経歴書・エントリーシートを HTML/CSS で生成し、`job-application-docs/` ディレクトリに保存する。

## 対応書類

| 書類 | 略称 | 記載項目 |
|------|------|---------|
| 履歴書 | rirekisho | `LOAD references/rirekisho-fields.md` |
| 職務経歴書 | shokumu-keirekisho | `LOAD references/shokumu-keirekisho-fields.md` |
| エントリーシート | entry-sheet | `LOAD references/entry-sheet-fields.md` |

## 必須ヒアリング項目

書類を生成する前に **必ず以下を確認** する。指示がない項目は推測せず、ユーザーに質問する。

1. **書類の種類** （履歴書 / 職務経歴書 / エントリーシート）
2. **記載内容** （氏名・学歴・職歴・志望動機など、書類に応じた必要項目）
   - 書類ごとの必要項目は、「対応書類」の表にある記載項目の「必須ヒアリング項目」にある

## 用紙と体裁の既定値

用紙サイズ・向き・デザインスタイルは質問しない。指定がなければ次の既定値で作り、使った既定値をユーザーへのメッセージで伝えて、変えたい場合は指定してもらう（記載内容を質問するときは、その質問に含める）。

| 項目 | 既定値 | ほかに指定できるもの |
|------|------|------|
| 用紙サイズ | A4 | B5（JIS B5）、US Letter など |
| 用紙の向き | 縦 | 横（履歴書だけ。2枚組を左右に並べた見開きにする） |
| デザインスタイル | `japanese-formal` | `modern-simple` |

- 職務経歴書とエントリーシートは縦だけで作る。横を指定されたら、縦で作ることを伝える
- 履歴書の見開きの作り方は rirekisho-fields.md の「横向き（見開き）」にある

## デザインスタイル

| スタイル | 特徴 | テンプレートパス |
|---------|------|----------------|
| `japanese-formal` | 厚生労働省の様式例寄り・罫線あり・伝統的 | `templates/japanese-formal/` |
| `modern-simple` | 罫線少なめ・余白を活かしたモダン | `templates/modern-simple/` |

## 生成ルール

1. **HTML/CSS のみで構成する。** JavaScript は一切含めない（`<script>` タグを書かない）
2. **PDF 化を見据えた構成にする。** 印刷・PDF 化で崩れる、または意味を持たない CSS / HTML は使わない
3. **用紙サイズを CSS で明示する。** `@page` の `size` を必ず指定し、`.page` に用紙の実寸を mm で指定する
4. **CSS は `<style>` タグ内に同梱し、単一の HTML で完結させる。** 外部 CSS ファイルや CDN を参照しない
5. **PDF 変換処理は行わない。** HTML ファイルのみを生成し、`.pdf` 出力やライブラリ（puppeteer 等）は使わない

使わない CSS / HTML の一覧と、ページサイズ・改ページなどの書き方は `LOAD references/pdf-safe-css.md` にある。

## 出力先

プロジェクトルート直下の `job-application-docs/` ディレクトリに保存する。書類には氏名・住所・生年月日などの個人情報が入るため、git に入らないようにする。

```
job-application-docs/
├── .gitignore                        # 「*」の1行だけ。ディレクトリごと git の管理外にする
├── rirekisho_YYYYMMDD.html
├── shokumu-keirekisho_YYYYMMDD.html
└── entry-sheet_YYYYMMDD.html
```

- `job-application-docs/` が存在しなければ作成する。中に `.gitignore` がなければ、`*` の1行だけを書いて作る
- ファイル名は `<略称>_<YYYYMMDD>.html` 形式にする。日付は書類を生成した日
- HTML の `<title>` は `<書類名>_<氏名>_<YYYYMMDD>`（例: `履歴書_山田花子_20261017`）にする。ブラウザで PDF に保存するときの既定のファイル名になる。氏名の間の空白は詰め、日付はファイル名と同じにする
- 同名ファイルがあれば `_2`, `_3` を付ける
- 生成した書類は、ユーザーに明示的に頼まれない限り git に追加・コミットしない

## ワークフロー

1. 書類の種類を確認する
2. その書類の記載項目（「対応書類」の表）を読む
3. 残りの **必須ヒアリング項目** をすべて確認する。用紙と体裁は質問せず、「用紙と体裁の既定値」に従う
4. `templates/<スタイル>/<略称>.html` をテンプレートとして読み込み、pdf-safe-css.md を読む
5. 「テンプレートの使い方」に従い、ユーザーの入力でテンプレートを埋めて HTML を生成する
6. 「出力先」に従って `job-application-docs/` に書き出す
7. 書き出した HTML を確かめ、問題があれば直す
   - pdf-safe-css.md の「9. チェックリスト」を満たしている
   - `{{` と `}}` が残っていない
   - 履歴書は、行数と字数が rirekisho-fields.md の「1枚に入る量の目安」に収まっている
   - エントリーシートは、各回答が文字数制限に収まっている（句読点を含めて数え、改行は数えない。応募先の数え方が分かればそれに従う）。超えていたら、ユーザーの文章を勝手に削らず、設問と字数を伝えて短くするか確認する
8. ファイルパスを伝え、ブラウザで開いて確認でき、印刷機能で PDF として保存できることを案内する。あわせて、使った既定値と、書類には個人情報が含まれ `job-application-docs/` は git の管理外にしてあることを伝える

## テンプレートの使い方

`templates/` 配下の HTML は **A4 縦** をデフォルトとしたサンプルである。

- ユーザーが他の用紙サイズを指定した場合は、`@page` の `size` と `.page` の `width` / `height`（または `min-height`）を必ず変更する。B5 の指定方法は pdf-safe-css.md の「1. ページサイズの指定」にある
- 履歴書は2枚組で、1枚目に基本情報と学歴・職歴、2枚目に免許・資格以降を書く。1枚に入る行数・字数の目安は rirekisho-fields.md の「1枚に入る量の目安」にある
- 職務経歴書とエントリーシートは1つの `.page` に書く。1枚を超えても自動で改ページされ、どのページにも余白が付くので、`.page` を分けない
- `{{…}}` はプレースホルダーで、すべてユーザーの入力に置き換え、出力に残さない。中身は項目名のほか、`:` の後ろに記入例や目安を添えたもの（`{{作成日: 2026年5月10日 現在}}`）、書式（`{{YYYY/MM 〜 YYYY/MM}}`）、選択肢（`{{正社員/契約}}`）、書き方の指示（`{{箇条書きで記載}}`）がある。`{{}}` は値を書き入れる空欄を表す
- 学歴・職歴、資格、プロジェクト、エントリーシートの設問など、繰り返す行やブロックは、内容と件数をユーザーの入力に合わせる
- 情報のない任意項目（△）は空欄のまま残さず、その行や欄を削除する（例: 職務経歴書の「規模」で資本金だけ分からなければ、資本金の部分を消す）。ただし写真欄は、写真のデータがなくても枠を残す（印刷後に貼れるようにするため）。応募先が写真を求めないと分かっている場合だけ消す
